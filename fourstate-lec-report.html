Result: 23 / 112 modules invalid under 4-state (19 unknown: hw.wire/bitcast/array_get, hwarith, i0, test.* not yet in 4-state encoder). Each card now shows inputs + outputs of both sides under the Z3 counterexample.

Can this be cross-checked with Verilator / iverilog?

Verilator: no (2-state only). Verilator is a 2-state simulator — X/Z are converted to 0 (see Verilator docs “Unknown values”: Verilator does not model X/Z; X is treated as 0). So mux(Z,10,00) etc. all simulate as 2-state and would report equiv, hiding the bugs. Useful only to confirm 2-state equiv.

Icarus Verilog (iverilog + vvp): yes, 4-state. Icarus implements full Verilog 4-state (0/1/x/z) with LRM truth tables (0&x=0, 1|x=1, mux(x,a,b)=agree-else-x, arithmetic with x→x), matching our SMT encoding. Example for muxConstantInputs:

module c1(input c, output [1:0] o); assign o = c ? 2'b10 : 2'b00; endmodule
module c2(input c, output [1:0] o); assign o = {c, 1'b0}; endmodule
module tb; reg c; wire [1:0] o1,o2; c1 i1(c,o1); c2 i2(c,o2);
initial begin c=1'bz; #1; $display("c=z o1=%b o2=%b %s",o1,o2,(o1===o2)?"EQ":"DIFF"); end endmodule
# iverilog -o sim sim.v && vvp sim
# c=z o1=x0 o2=z0 DIFF   <- matches our card: Before X0 vs After Z0

Not installed in this container (iverilog: command not found), but the testbench above reproduces every card: drive inputs with the X/Z values from the counterexample table (e.g. 1'bz, 4'b00X0), compare with case-equality === (exact 4-state, like our distinct on 2N bits). Yosys sim is also 4-state at RTLIL level (Sx/Sz bits) but its stimulus flow (clock/FST/witness) is awkward for pure comb; iverilog/VCS/Questa are the idiomatic 4-state checks. Our Python int-based evaluator in /tmp/eval4.py + run_outputs2.py implements the same LRM tables and agrees with iverilog semantics.
